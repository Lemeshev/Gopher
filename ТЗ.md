# Gopher Life — ТЗ, правила процесса и критерии приёмки (v1.3.0)

> **Этот файл — единственный источник истины по задаче.**
> Если вывод исполнителя противоречит этому файлу — прав файл.
> Если требование заказчика противоречит файлу — **спроси заказчика, не догадывайся**.
> Файл написан так, чтобы работу можно было передать другому исполнителю
> (человеку или ИИ) без устных пояснений и без «контекста в голове».

## 0. Кратко о задаче

Заказчик получил HTML5/Canvas тамагочи-игру **Gopher Life** (папка `www/`),
обёрнутую в Android WebView (`android/`). Текущая версия — **1.3.0**
(`GAME_VERSION` в `www/js/helpers.js`, `version` в `package.json`,
`versionName` в `android/app/build.gradle`).

От исполнителя требуется:

1. Довести игру до состояния «работает на телефоне», починив все известные баги.
2. Собрать **подписанный release APK** и положить его на рабочий стол как
   **`Gopher.apk`** (имя файла — требование заказчика, не «как получилось»).
3. Доказать работоспособность **независимыми ревьюерами**, а не словами.
4. Держать этот файл в актуальном состоянии: **любое требование заказчика
   сначала попадает сюда**, потом в код и в проверку.

## 1. ГЛАВНОЕ ПРАВИЛО ПРОЦЕССА (требование заказчика, дословно)

> «После КАЖДОЙ правки КАЖДЫЙ из 4 ревьюеров заново с нуля проверяют ВЕСЬ
> процесс. Только когда ВСЕ ревьюеры согласны — тогда двигаемся дальше.
> Когда ВСЁ сделано — все всё проверяют ещё раз. Исходя из всех условий задачи.»

### Как это исполнять буквально

1. **Любая правка** (одна строка, файл, конфиг, картинка) → **полный прогон
   всех ревьюеров с нуля** по всему проекту. Не «только изменённый файл»,
   не «это я уже проверял», не «правка косметическая».
2. **«С нуля»** = команды запускаются заново, весь набор проверок, по всему
   проекту, без опоры на память о прошлом прогоне.
3. **Пока есть хоть один красный пункт у любого ревьюера — следующую правку
   не начинать.** Сначала зелёный прогон, потом следующий шаг.
4. **Вердикт выносится по ПОЛНОМУ списку условий** (раздел 4), а не по тому,
   что исполнитель вспомнил. Не записано в условия/проверку — значит для
   приёмки не существует.
5. **Финальный прогон.** Когда исполнитель считает, что всё сделано — все
   ревьюеры прогоняются **ещё раз** с нуля, по всем условиям, и только тогда
   результат объявляется готовым.
6. **Отчёт только фактами.** Каждое «сделано» подтверждается выводом команды,
   скриншотом или md5. Чего проверить не удалось — так и писать
   «не проверено» с причиной, а не «работает».

### Про количество ревьюеров (важно, не путаться)

Заказчик требует **4 независимых ревьюера**. В проекте их **5**:
4 «логических» + 5-й **рендер** (`tools/render-check.js`), который добавлен
принудительно, потому что ревьюеры 1–4 работают на **заглушке canvas** и по
устройству не могут увидеть пиксели (см. раздел 6).

Правило из п. 1–6 распространяется на **всех пятерых**, плюс есть отдельные
блоки проверок требований v1.2 («ревьюер 1/5 доп.» и «ревьюер 3/5 доп.»):

```bash
cd ~/gopher/gopher-life
npm run verify      # ожидается "пройдено NN | провалено 0", код выхода 0
```

Для быстрой итерации во время разработки есть дешёвый прогон **без Chrome**
(логика, комнаты, энергия, коды, персонажи, кадры всех сцен):

```bash
node tools/quickcheck.js    # ~2 секунды, ожидается "провалено 0"
```

`quickcheck` — **вспомогательный** инструмент. Приёмка считается пройденной
только по `npm run verify` (все 5 ревьюеров) и по просмотру кадров глазами.

## 2. Что именно нужно сдать (deliverable)

| Что | Требование | Как проверяется |
|---|---|---|
| Файл сборки | `~/Desktop/Gopher.apk` — имя **ровно** `Gopher.apk` | `ls ~/Desktop/Gopher.apk` |
| Тип сборки | подписанный **release** (не debug) | ревьюер 4/5 |
| Подпись | релизным ключом проекта, `CN=Gopher Life` | ревьюер 4/5 (`keytool`) |
| Содержимое | внутри APK актуальный код, а не старый | ревьюер 4/5 (сверка с `www/`) |
| Запуск | игра стартует с иконки, экран **не чёрный** | ревьюер 2/5 + 5/5 |
| Иконка | видна и корректна на Android 5.0–15 (API 21+) | ревьюер 1/5 |
| Интерфейс | русский, без сырых английских значений | ревьюер 1/5 + глазами |
| Экраны | ничего не обрезано и не наложено | **глазами** по `preview/screens/` |
| Кадры | `preview/screens/` содержит свежие PNG всех сцен | `npm run render -- --shots=preview/screens` |

**Итог задачи — не «код в репозитории», а рабочий APK на рабочем столе
плюс зелёный прогон всех ревьюеров.**

## 3. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

Ниже — что игра обязана делать. Каждое требование подтверждается проверкой
в `tools/verify.js` (номер блока указан после пункта) или глазами по кадрам.
Обозначения: **[1]** статика, **[2]** запуск/кадры, **[3]** клики/механика,
**[4]** APK, **[5]** реальный рендер, **[Г]** глазами.

### 3.1 Дом и действия [1][2][3][Г]

- [ ] Дома есть четыре комнаты и переключатель комнат над комнатой.
- [ ] Панель характеристик — 6 шкал (счастье, сытость, энергия, чистота,
      здоровье, стресс), ничего не обрезано, стресс — с перевёрнутыми цветами.
- [ ] Строка «Стресс» нажимаемая: открывает справку «как снизить стресс»,
      рядом видна подсказка «нажми на «Стресс»…».
- [ ] Действия: Покормить, Искупать, Уложить спать/Разбудить, Играть, Музыка,
      Тихие игры, Обстановка, Карта — 8 кнопок в двух рядах.
- [ ] Каждое действие привязано к комнате: покормить — кухня, купать — ванная,
      спать — спальня, играть/музыка — гостиная. Если комната не та, питомец
      сам идёт туда («Идём в спальню»), на кнопке виден значок комнаты.
- [ ] «Покормить» реально повышает сытость (эталон: 70 → 95).
- [ ] Кормление/купание/игра/сон сопровождаются видимыми эффектами
      (еда в лапе и крошки, вода и пузыри, мяч, «Zzz»).
- [ ] Музыка играет ~8 секунд, летят нотки, стресс снижается.
- [ ] Верхняя панель: монеты, уровень, XP-полоса, маленькая кнопка
      «обстановка» (≤ 36 px — её трудно нажать случайно).

### 3.2 Комнаты и мебель [1][2][3][5][Г]

- [ ] Комнат четыре: **гостиная, спальня, кухня, ванная**
      (`HOME_ROOMS`, у каждой своя бесплатная отделка по умолчанию).
- [ ] У каждой комнаты свои обои, пол и **своя мебель**; переключение комнаты
      перерисовывает комнату целиком.
- [ ] Мебель покупается в магазине и попадает **в свою комнату** (диван —
      в гостиную, кровать — в спальню, холодильник — на кухню, ванна — в ванную).
- [ ] Предмет можно перетаскивать внутри комнаты (палец), ставить из инвентаря
      и убирать в инвентарь.
- [ ] Предмет, не подходящий комнате, не ставится: показывается, где его место.
- [ ] В каталоге **не меньше 45 предметов**, у каждого уровень цены
      (дёшево / средне / дорого / роскошь) — есть что копить: мебель дороже
      900–3500 монет (персидский ковёр, рояль, камин, кровать с балдахином).
- [ ] Есть разные варианты одного типа мебели (кровати: раскладушка → кровать →
      двуспальная → с балдахином; шкафы, столы, ковры, холодильники, диваны).
- [ ] **Соразмерность:** мебель на переднем плане крупнее, чем в глубине
      (перспектива `RoomView.depthScale`), и у предметов разный «истинный» размер
      `k` (шкаф выше часов, кровать шире тумбочки).
- [ ] Маленькая вещь в глубине комнаты читается как «стоит далеко»;
      большая кровать на переднем плане не меньше фигурки питомца.
- [ ] Мебель ближнего плана рисуется **перед** питомцем, дальнего — за ним
      (два слоя по линии глубины `gopherDepthLine`).

### 3.3 Цвета и отделка (за деньги) [1][3][5]

- [ ] У каждого предмета есть палитра (≥ 4 цвета); выбранный цвет сохраняется.
- [ ] Перекраска платная: цена зависит от стоимости предмета
      (`recolorCost = max(8, 10% цены)`), без денег показывается «Нужно N монет».
- [ ] Ключевая мебель нарисована кодом (не эмодзи), поэтому перекраска видна
      глазом (диван, кровать, шкаф, стол, холодильник, ванна, ковёр и др.).
- [ ] Обои и пол продаются наборами (в том числе дорогие: «Ночное небо» 900,
      «Мрамор» 1500, «Золотой пол» 2000); купленный набор применяется бесплатно.
- [ ] Каждую комнату можно перекрасить независимо от других.

### 3.4 Энергия и сон, включая закрытое приложение [1][3]

- [ ] Поход в локацию стоит **2–8 энергии** (`System.VISIT_ENERGY`), пассивная
      трата — **1.5 энергии в час**, сон — **+10% в минуту**.
- [ ] Семь походов подряд оставляют больше половины шкалы (проверка в [3]).
- [ ] Энергия больше не «сгорает за два похода»: работа блокируется только
      при энергии < 15, учёба < 10, парк/зал/кино < 5.
- [ ] Причина отказа объясняется словами: «Гофер устал — сначала поспи 😴»,
      «Гофер голодный — сначала покорми 🍕».
- [ ] Гофера можно уложить спать и **полностью закрыть приложение** — энергия
      всё равно восстанавливается (`System.applyOfflineProgress`), через
      10 минут он просыпается сам, о чём игра сообщает в облачке.
- [ ] **Пока гофер спит, дела с ним невозможны** (v1.2.1, замечание заказчика):
      походы (музеи, работа, учёба, спортзал, парк, бассейн, ресторан, кино,
      библиотека, поликлиника, друзья) и домашние действия (покормить, искупать,
      играть, музыка) закрыты — спящий питомец не может оказаться в музее или
      на работе. `System.isLocationAvailable()` учитывает сон, `System.sleepBlocks()`
      перечисляет закрытое, `SLEEP_ALLOWED` — открытое.
- [ ] Пока гофер спит, **открыто то, что от него не зависит**: дом, тихие игры,
      мини-игры, магазин (это каталог) и инфо/настройки. На карте это видно
      (плитки с 💤 и надпись «Гофер спит — походы закрыты»), дома — выключенными
      кнопками с подсказкой «Гофер спит 💤 — сначала разбуди» и плашкой
      «Открыто: тихие игры · мини-игры · магазин · инфо».
- [ ] Причина отказа во сне объясняется словами: «Гофер спит 💤 — походы
      подождут. Сейчас можно: тихие игры, мини-игры, магазин и инфо».
- [ ] Выспавшийся питомец (энергия 100%) **просыпается сам и в открытой игре**
      (то же поведение, что и с закрытым приложением) — об этом говорит облачко
      «☀️ Гофер выспался!». Уложить спать при полной энергии нельзя: игра
      отвечает «Гофер и так полон сил ⚡».
- [ ] Бодрым офлайн-траты мягкие и не опускают шкалы ниже «пола»
      (энергия ≥ 25, сытость ≥ 25, чистота ≥ 30, здоровье ≥ 40, стресс ≤ 25):
      ребёнок не возвращается к измученному питомцу.
- [ ] Игра сохраняется при сворачивании/закрытии (`visibilitychange`, `pagehide`).

### 3.5 Стресс и спокойные занятия [1][3][Г]

- [ ] Стресс объясняется прямо в игре: экран справки по каждой шкале
      (что повышает, что понижает) — вкладка «❓» в статистике и строка «Стресс».
- [ ] Стресс снижают: сон, музыка дома, купание, игра, тихие игры,
      поликлиника, ресторан; повышают: голод, время, походы без отдыха.
- [ ] Если стресс ≥ 40, в облачке дома появляется подсказка, что делать.

### 3.6 Тихие игры (пока питомец спит) [1][2][3][5]

- [ ] Есть сцена «Тихие игры» (`quiet`) с тремя занятиями: **Созвездие**,
      **Раскраска**, **Тихая рыбалка**.
- [ ] Пока гофер спит, доступны и **мини-игры** (`minigames`: крестики-нолики,
      Memory, монетка) — они не зависят от питомца; на экране мини-игр написано
      «💤 Гофер спит — играй, энергия копится сама».
- [ ] В тихих играх **нельзя проиграть**, они **не тратят энергию** и дают
      8–12 монет + опыт + снижают стресс.
- [ ] В шапке видно состояние питомца: «Гофер спит 💤 энергия NN% (+10% в минуту)».
- [ ] Застрять нельзя: у каждой игры есть «Заново / Новая».

### 3.7 Карта, локации и спорт [1][2][3][5]

- [ ] Карта открывает все локации; за поход списывается энергия (2–8, видно
      бейджем **⚡N** прямо на плитке локации, до нажатия) и слегка идёт
      время (0.5 ч), с проверкой «можно ли» и человеческой причиной отказа.
- [ ] В спортзале есть особый пункт **«🎪 Воздушная гимнастика»** (`aerial`):
      питомец качается на кольцах, игрок жмёт «Прыгнуть» в зелёной зоне,
      есть точные/хорошие перелёты, 5 попыток, награда монетами и опытом.
- [ ] Гофер в каждой локации выглядит уместно (в бассейне — плавки, на работе —
      галстук, в зале — повязка, в библиотеке — очки с книгой и т.д.).

### 3.8 Поликлиника: видно, как лечат [1][2][3][5][Г]

- [ ] Восемь процедур (`CLINIC_PROCEDURES`): рецепт, укол, проверка зрения
      по таблице, рентген, перевязка, осмотр зубов, витамины, градусник.
- [ ] Каждая процедура показывается **пошагово** (три подписанных шага) с
      полосой прогресса и своими элементами (шприц, таблица букв, снимок,
      бинт, фонарик, баночка витаминов, шкала температуры).
- [ ] Процедуры не повторяются, пока не показаны все восемь
      (`System.getSeen('clinicAnim')`).
- [ ] Кнопки: «💊 Пойти к врачу» → «✅ Забрать лечение»; после лечения
      здоровье +30, стресс −15.

### 3.9 Друзья: коды, которые реально работают [1][3][Г]

- [ ] **Копирование работает:** код копируется кнопкой через настоящий
      `<textarea>` (`document.execCommand('copy')`) с запасным
      `navigator.clipboard.writeText` — в canvas выделить текст нельзя, поэтому
      поля вынесены в разметку (`#clipPanel`).
- [ ] **Вставка работает:** есть поле ввода, куда WebView сам показывает меню
      Android («Вставить»), плюс кнопка «📥 Вставить из буфера».
- [ ] **Есть короткий код: 16 символов** группами по 4 (`844Q-0082-4R3N-H2H7`)
      с контрольным символом: его можно **продиктовать или набрать руками**.
      В нём обои, пол, окрас, персонаж и 6 предметов комнаты.
- [ ] Есть кнопка «📤 Отправить» (системное «Поделиться», иначе SMS, иначе копия).
- [ ] Полный код (весь дом со всеми комнатами) копируется/вставляется кнопкой.
- [ ] Опечатка в коротком коде распознаётся (контрольная сумма) и объясняется.
- [ ] Друг добавляется по любому из двух форматов; повторно тот же друг
      не добавляется.
- [ ] В гостях видно комнату друга (та же отрисовка, что дома), его персонажа
      и окрас; работают «Поболтать», «Подарок», рост дружбы.

### 3.10 Профили и персонажи [1][3][5]

- [ ] Профили: до 4, каждый со своим сохранением, именем, комнатой и прогрессом.
- [ ] **Задел заказчика: герой — не только гофер.** Персонаж — это описание
      (`CHARACTERS` в `www/js/characters.js`), а не жёстко вшитый маскот:
      сейчас доступны **Гофер, Мишка, Зайка, Котёнок, Робот и Милка**.
- [ ] **Милка** (v1.2.1, по фотографиям плюшевой игрушки заказчика): белая,
      длинные уши с зелёной подкладкой, зелёные вышитые глаза, румянец, розовый
      ротик, крылышки с зелёными подушечками, розовые подушечки на лапках,
      пушистый хвост и хохолок между ушами. Превью — `preview/milka.png`,
      `preview/milka_sleeping.png` (`node tools/render-gopher.js … --char=milka`).
- [ ] Персонажа можно выбрать в меню («🧸 Персонаж») с живым превью, выбор
      сохраняется в профиле и переносится в игру, в гости и в код друга.
- [ ] Добавление новой игрушки = **один объект в `CHARACTERS`** плюс (при
      желании) свои уши/хвост/палитра; сцены менять не нужно.
- [ ] У каждого персонажа свои цвет тела, лапы, нос, морда, уши, хвост, зубы,
      усы, визор; работают все выражения (happy/sleeping/excited/sad/sick/eating),
      аксессуары (шляпы, очки, бабочка), экипировка (плавки/галстук/повязка),
      предмет в лапе и вода.

### 3.11 Магазин [1][2][3][5]

- [ ] Вкладки: Еда, Игрушки, Одежда, **Дом**, Веселье; вкладка «Дом» —
      фильтры по четырём комнатам и по виду товара (Мебель / Обои / Пол).
- [ ] Карточки показывают название, описание, комнату и уровень цены;

## 5. Команды и обязательный цикл после КАЖДОЙ правки

```bash
cd ~/gopher/gopher-life

# 1) Быстрая проверка логики (2 секунды, без браузера)
node tools/quickcheck.js

# 2) Полная сборка: sync www→assets, gradle release, копия на рабочий стол
npm run apk:desktop        # ~1 мин

# 3) Полный прогон ВСЕХ ревьюеров с нуля (главное правило раздела 1)
npm run verify             # ~10–20 мин (Chrome, 58 сцен)

# 4) Свежие кадры всех сцен для глаз
npm run render -- --shots=preview/screens
```

**Почему именно такой порядок и почему его нельзя менять:**

- Ревьюер 4/5 сверяет **содержимое APK с исходниками**. Если правка сделана
  в `www/`, но APK не пересобран — ревьюер 4 падает на «JS внутри APK устарели».
  Поэтому: **сначала сборка, потом проверка.**
- `npm run build` сам вызывает `tools/sync-www.js`, который копирует `www/`
  в `android/app/src/main/assets/www/` и удаляет оттуда устаревшие файлы.
  Руками копировать нельзя — забудется (это и был «чёрный экран»).
- Ревьюер 5/5 требует установленный **Google Chrome** (путь можно задать через
  переменную `CHROME_BIN`) и идёт дольше остальных: при 58 сценах — примерно
  5–10 минут. Пока он идёт, новые правки не начинать, иначе проверяется уже
  не тот код.

## 6. Почему исполнитель обсирается — разбор без отговорок

Ниже — что именно ломалось в v1.0, почему это проходило сквозь «зелёные»
проверки и какая системная причина за этим стоит. Читать до начала работы.

### 6.1 Факты провалов

| № | Что случилось | Почему проверки это пропустили |
|---|---|---|
| 1 | **Чёрный экран** в собранном APK | APK собирался из `android/.../assets/www/`, а правки шли в `www/`. Копия устарела. Проверок «APK == исходники» не было, синхронизация была ручной. |
| 2 | **Не работали кнопки нигде** | `createButton()` возвращал объект без поля `text`, а сцены проверяли `btn.text`. Кликов не тестировали вообще. |
| 3 | **Пустая иконка на Android 5–7** | Иконка была VectorDrawable; на API 21–25 launcher её не рисует. Проверялось «файл существует», а не «работает на целевых API». |
| 4 | **Имя файла не то** | Требовалось `Gopher.apk`, отдавалось `GopherLife.apk`; требование не было записано ни в одну проверку. |
| 5 | **Вёрстка сломана, а «пройдено»** | Ревьюеры 1–4 работают на заглушке canvas: код выполнился, исключений нет — «успех». Что нарисовалось, не видно: обрезанные кнопки, наложения, `morning` вместо «Утро». |
| 6 | **Ложный диагноз исполнителя** | Первый прогон реального рендера выдал «чёрный экран» — оказалось, баг самого стенда (`var f = g.loop; f()` теряет `this`). |

### 6.4 Что нашло финальное само-ревью v1.2 (заказчик + ревьюер) и что добавлено в проверки

## 8. Слабые места автоматики — НЕ считать закрытым

1. **Наложение и обрезка элементов не детектится автоматикой.** Ревьюер 5/5
   видит только «кадр не пустой». После каждой правки вёрстки — **обязательный
   ручной просмотр** `preview/screens/*.png`.
2. **Проверяется один размер экрана** (headless-окно 390×844, канвас ~500×744).
   Маленькие экраны, планшеты, вырезы и системные панели не покрыты.
3. **Ревьюер 5/5 требует Chrome** и идёт долго (58 сцен); при загруженной
   машине Chrome иногда не отвечает — встроено 3 попытки на сцену.
4. **Живое устройство тестируется вручную на эмуляторе, а не автоматикой.**
   В v1.3.0 эмулятор поднят и чек-лист пройден (раздел 4.6) — и он сразу нашёл
   два отличия от Chrome: наряд в меню после перезапуска и недоступный буфер
   обмена в WebView. Автоматики на этот прогон нет: он повторяется руками.
   Физического телефона (не эмулятора) у исполнителя по-прежнему нет: экран
   1080×2340, свежие версии Android WebView и настоящий звук — вне проверок.
5. **Звук замокан** (`AudioSys` подменяется в стенде). Голоса героев проверяются
   как «число нот и уникальность тембра» поддельным аудиоконтекстом — как это
   звучит на телефоне, слышно только руками.
6. **Долгие таймеры** (автосохранение, офлайн-прогресс) прокручиваются
   искусственно; реальные сутки ожидания не проверялись.
7. **Дни достижений считаются по часам устройства.** Симуляция 400 дней
   прокручивает даты программно, поэтому она доказывает «раньше срока нельзя»,
   но не доказывает «жульничество с переводом часов невозможно» — это открытый
   вопрос 7 в разделе 7 (рекомендация: оставить как есть).
8. **Кривая темпа — модель, а не живой ребёнок.** В симуляции «обычный день» —
   это 6 походов, 4 мини-игры, 120 монет и 250 XP. Если реальный игрок играет
   реже, долгие награды придут позже; если чаще — часть «недельных» можно взять
   на 3–4-й день (но «месячные» — всё равно только по дням).

## 9. Пошаговый цикл для преемника

1. Прочитать этот файл **целиком** (особенно разделы 1, 6, 8).
2. Зафиксировать исходное состояние:
   ```bash
   node tools/quickcheck.js && npm run apk:desktop && npm run verify
   ```
   Записать фактические цифры и код выхода.
3. Открыть глазами все PNG из `preview/screens/` и составить список визуальных
   дефектов (обрезано / наложено / нечитаемо).
4. Любое требование, у которого нет проверки, — **сначала** превратить в
   проверку в `tools/verify.js` (или в новый инструмент), и только потом
   править код.
5. Вносить правки **по одной**.
6. **После каждой правки**: `node tools/quickcheck.js` → `npm run apk:desktop`
   → `npm run verify` → `npm run render -- --shots=preview/screens` →
   просмотр PNG глазами. Есть красный пункт — дальше не идти, чинить.
7. Когда всё зелёное и глазами чисто — **финальный полный прогон заново**.
8. Отчёт заказчику строго по формату из раздела 11. Всё, что не проверено,
   перечислить явно (разделы 4.6 и 8).

## 13. Как добавить нового героя (инструкция на v1.4)

1. Открыть `www/js/characters.js` и добавить объект в `CHARACTERS`:
   `id`, `name`, `emoji`, `desc`, палитра (`body`, `limb`, `nose`),
   уши (`ears.style`: `round` / `long` / `pointy` / `antenna`, плюс `ears.tilt`
   и `ears.inner`), хвост (`tail`: `none` / `puff` / `thin` / `plush`),
   `muzzle`, `teeth`, `whiskers`, `shape`, а при желании — «своё»:
   `eyeStyle: 'oval'` + `eyeColor` (вышитые глаза), `cheeks`, `mouth`,
   `noseScale`, `tuft`, `pads` (подушечки на лапках),
   `wings: { spread, dy, rx, ry, tilt, pad }`.
2. **Обязательно с v1.3 — `voice`** (голос героя, `AudioSys.voice`):
   `voice: { base: <Гц>, type: 'sine' | 'triangle' | 'square' | 'sawtooth',
   steps: [1, 1.5], dur: 0.12, bend: 1.1 }`. Тембр (`base` + `type`) должен
   **отличаться от остальных героев** — это проверяет `tools/verify.js`.
3. **Если герой ушастый** (длинные уши, рога, антенна) — задать посадку
   головного убора: `hat: { shift: 0.018, scale: 0.92 }` (как у Милки), иначе
   шляпа будет спорить с ушами. Наряды подключать не нужно: слоты `hat`,
   `glasses`, `neck`, `back` рисуются общими методами `drawAccessories` и
   `drawBackItems`.
4. Больше ничего менять не нужно: выбор в меню, превью, наряды, голос, коды
   друзей, гости, локации и все выражения подхватят персонажа автоматически.
5. Добавить проверку в `tools/verify.js` (счётчик персонажей) и кадр в
   `tools/render-check.js` (`home~look=char:<id>,hat:cap,neck:scarf`), чтобы
   было видно, как на новом герое сидят наряды.
6. Прогнать полный цикл из раздела 5 и обновить раздел 12.
